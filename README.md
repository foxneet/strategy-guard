# 策略守护壳（strategy-guard）

**定时启动/重启 + 意外终止自动拉起，通用命令行策略进程守护（Windows GUI）。**

给"无人值守实盘"补最后一块拼图：策略进程崩了谁拉起来？每天几点重启？崩在什么时候、退出码是什么——守护壳替你盯着。

## 它解决什么

跑实盘策略的人都会遇到：

- **收盘后才发现策略上午 10 点就崩了**，中间信号全丢——keep_alive 模式在进程退出（崩溃/被关窗/正常结束）后，冷却 N 秒自动拉起；
- **策略跑几天内存涨/状态漂**，需要每日重启，但手动重启总忘记或撞上开盘——daily_time 模式每天到点：在跑就杀掉换新进程，没跑就直接拉起，跨天只触发一次；
- **多策略同守**，崩了不知道是谁——每个目标可填备注，日志按"名称（备注）"标注，主界面带备注列；
- **事后追责没证据**——日志每日滚动（`logs/守护_YYYYMMDD.log`，自动保留 30 天），记录全部生命周期事件：启动/退出（含退出码）/定时重启/终止。

两种守护机制可叠加，停止按钮=人工停止（不再拉起，直到点"立即启动"）。

## 实盘迭代补上的功能

工具先在自己实盘跑，踩到什么补什么（`docs/说明.txt` 有每版的完整备注）：

- **显示策略窗口（默认开）**：每个策略跑在独立控制台窗口，日志都在窗口里；关掉=隐藏后台运行（主界面仍显示状态与 PID）。修掉了 GUI 父进程拉起控制台窗口默认隐藏的 Windows 坑（显式 STARTF_USESHOWWINDOW）；
- **工作目录**：策略进程以此为当前目录——相对路径读写、同目录资源调用全以它为基准，可空=继承守护壳所在目录；"浏览..."选脚本自动生成 `py -3.14 "<绝对路径>"`，脚本位置与运行目录互不影响；
- **窗口保持（调试用）**：`cmd /k` 启动，策略退出/崩溃后控制台不关窗，报错停在窗口里。注意保持期间守护壳无法监测存活，靠每日定时兜底；调试完关掉；
- **前置窗口 / 测试运行**：一键把策略控制台强制还原并置前（排查"程序活着却看不到窗口"）；测试运行=新窗口跑一次命令（cmd /k 保持），不占用受守护实例；
- **退出码排查**：9009=命令或路径不存在；2=策略致命退出；0=正常结束（A 类扫描完成属正常）。守护日志里全有；
- **开机自启**：写当前用户注册表 Run 键（HKCU）。刻意不走任务计划程序——勾了"不管用户是否登录都运行"会跑在 Session 0，策略子进程活着但**所有窗口对你不可见**，这是最常见的误配；
- **不允许重复运行（每策略）**：启动前用 PowerShell 扫全进程命令行，发现同脚本进程（含手动双击启动的）就拒绝本次启动并记 PID，30 秒后复查——防多实例写坏同一份数据/信号。代价是启动前 1~3 秒扫描；
- **单实例保护（整机，默认开）**：守护壳本体用 Global 命名互斥体，双击第二次/自启+手启都弹窗拒绝，跨会话整机级防双开。确需双实例：在运行中的守护壳点"单实例保护:关"再启第二个。

## 快速上手

```bash
# 方式一：免安装 exe（Releases 下载，双击即用）
# 方式二：源码运行
py -3.14 策略守护壳.py            # GUI
py -3.14 策略守护壳.py --selftest # 无界面自检（调度/守护逻辑）
```

每个守护目标 = 一条命令行。配置持久化在 exe 同目录的 `守护壳配置.json`。

**调度建议**：每日定时设在 09:10 这类开盘前空档，避开 09:25-09:30 和 14:55-15:01 的关键交易窗。

## 设计要点

- **纯标准库**（tkinter/subprocess/threading），无第三方依赖；
- **状态机对重启安全**：守护壳本身崩溃重启不会丢失目标状态；配合策略侧的执行账本（如消费账+持仓去重），保证不会因守护拉起而重复下单；
- **按天滚动日志**，30 天自动清理，多策略备注标注；
- **只守护不碰策略**：对策略的全部干预就是"启动"和"终止"两个进程级动作，不读写策略数据、不碰信号逻辑。
